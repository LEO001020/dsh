########################################################################
# 3. THE FIX IN THIS TREE
########################################################################
(a) The v1 defect is GONE AT THE SOURCE. `pendingDrain` no longer exists as the
    coalescer; host.ts:408-418 documents its replacement:
      "Replaces the old `pendingDrain: Map<string, Promise<LaunchOutcome[]>>`, whose
       coalescing was a one-shot `await` that let every waiter start its own pass."
    and host.ts:1957-1975 quotes the old code and explains why the await was the
    mechanism that SYNCHRONIZED the callers rather than the protection:
      const inFlight = this.pendingDrain.get(runId)
      if (inFlight !== undefined) await inFlight          // awaits the OTHER drain
      const task = this.runDrain(runId, requests, signal) // <-- no re-check
    The replacement is a generation/dirty loop: one leader per run runs passes while
    `requestedGeneration > handledGeneration`, and an arrival during a pass only
    advances the generation and joins the leader.
(b) THE TARGET CHECK MOVED INSIDE THE STORAGE-DOMAIN UPDATE, which is what actually
    closes the hole. host.ts:1499 `if (held >= target)` sits INSIDE the
    `this.runs().update(...)` transform (opened at host.ts:1379), where the domain's
    per-run write chain serializes it against every other write to that run. That is
    the same place the BUDGET check already was, which is why the sibling case CAP-09
    never had this hole.

# 5. A MEASUREMENT BUG I MADE AND CORRECTED — the first reading was WRONG
########################################################################
My first attribution probe read `o.reason` off a LaunchOutcome and printed
`reason: 'none'` for the REFUSED third call, which reads as "refused with no reason".
That was MY bug, not the product's: `reason` is optional on LaunchOutcome
(host.ts:124-130) and `'none'` is the SUCCESS reason on the DIFFERENT
AdmissionReservation type (host.ts:142-149). The LaunchOutcome for a refused task
carries no reason at all, which is why the corrected probe above prints only the
taskId. The refusal is real and is produced by mayAdmit, established by ARM B.
