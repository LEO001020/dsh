The straddling write is SILENTLY ATTRIBUTED to the later cell: it is not late
(lateCount 0) and not flagged undecidable; it is folded into cell three's stdout,
where a model reading that result will attribute it to cell three's own code.

MECHANISM (platform fact, upstream of this project's router): ipykernel/iostream.py
resolves a stream's parent header from a contextvars.ContextVar, falling back to a
GLOBAL when unset. threading.Thread starts with an EMPTY context (an asyncio Task
would copy one), so a background writer takes the global — which holds whichever
cell most recently set it, i.e. the LATER cell. The kernel stamps the straddling
write with the later cell's msg_id before it is ever sent, so the broker's router
sees `parent == sink.msg_id` with the cell not yet idle and cannot separate the two.
