VER-07 - a verification failure does not permanently drain the run
==============================================================================

SPEC ORACLE, quoted:
  "Legitimate recovery continues, and `pause` has not been misused as a final
   drain. A run that cannot continue after a recoverable failure is NOT PASS."

THE MECHANISM UNDER MEASUREMENT, and why it is not a stylistic preference:
  `pause` is a RECORD change plus a refusal to admit new work; the run stays open and
  can be resumed. `drainContinuableDescendants` closes admission for that exact parent
  PERMANENTLY. If a failed acceptance used the drain, a verification failure would be
  terminal BY ACCIDENT -- the run could never be corrected. The case drives the REAL
  continuable stack, because the permanence is a property of the real `SubagentRuntime`
  and a stand-in could not have it.

THE ASSERTIONS THE CASE MAKES, read from the source rather than from a summary
  (packages/dsh-daily-work/src/verification-gates.test.ts, describe 'VER-08:
   after a verification failure a legitimate recovery can continue'):

  1. `pause` on a verification failure leaves the run PAUSED and refuses new admissions
     with reason 'run_not_open' -- so the failure really does stop admission:
         await rig.service.pause('run-ver08', 'acceptance failed: the candidate patch does not apply')
         expect(rig.service.getRun('run-ver08')?.phase).toBe('paused')
         expect(refused[0]?.accepted).toBe(false)
         expect(refused[0]?.reason).toBe('run_not_open')

  2. A CORRECTION CHILD can still be established while paused. This is the property a
     permanent drain would have destroyed, and it is asserted against the real runtime:
         const correction = await rig.ctx.subagents.startContinuable({ ... })
         expect(String(correction.childId)).toBe('ver08-correction')

  3. Resume is a real authorization edge, and after it the run admits again:
         await rig.service.resume('run-ver08')
         expect(rig.service.getRun('run-ver08')?.phase).toBe('open')
         expect(admitted[0]?.accepted).toBe(true)

  4. ONLY at the definite end is the permanent drain legal -- and AFTER it the same
     parent cannot admit, which is what proves the paused state above was genuinely
     'not yet drained' rather than a no-op:
         await rig.ctx.subagents.drainContinuableDescendants([rig.root])
         await expect(rig.ctx.subagents.startContinuable({ ... }))
           .rejects.toThrow(/draining; the operation was not admitted/)

  5. A failed acceptance is a RECEIPT, not a throw, so the caller can recover and retry
     in the same process with no residual state: outcome 'fail', exit.code 4, reasons
     non-empty, holdReservation false; the corrected re-run then PASSES.

failed -> corrected -> re-verified -> completed turn.
